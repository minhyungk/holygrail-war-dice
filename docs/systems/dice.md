# 주사위와 판정
상태: 규칙·상한·DC [확정] (D-073) · 관련: stats.md, phases.md, combat.md · constants 접두: `dice.`

## 1. 목적
모든 확률 판정을 하나의 규칙으로 통일한다. 이변(약자의 승리)이 가능하되 격차가 무의미하지 않게 한다.

## 2. 입력 / 출력 / 상태
- 입력: 판정 종류, 굴리는 쪽 스탯/보정 목록, (대항이면) 상대 스탯/보정 목록
- 출력: 자연값, 보정 후 값, 성공/실패(또는 승/패/동점), 차이(margin), 기적 여부
- 상태: 시드 RNG 상태, 운명점 잔량

## 3. 규칙
### 3.1 판정 [확정]
1. 판정값 = **2d10 자연값(2~20) + 보정치 합** (D-015) → `dice.die_count` = 2, `dice.die_size` = 10
2. 대항 판정: 양쪽이 굴려 판정값이 큰 쪽이 이긴다. 동점은 무승부.
   - 전투 국면의 동점은 국면 스킵 (`combat.md` §3.3, D-017)
   - 차이(margin) = 이긴 쪽 판정값 − 진 쪽 판정값. 국면의 상태 하락량에 쓰인다 (`combat.md` §3.4)
3. 단독 판정: 판정값 ≥ 난이도(DC)이면 성공.

### 3.2 DC [확정] (D-073) → `dice.dc`
단독 판정은 보통 2d10 + 스탯 1개(3~8)로 굴린다.
| 단계 | DC | 성공률 (스탯 E=3) | (C=5) | (A=7) | (EX=8) |
|---|---|---|---|---|---|
| 쉬움 | 12 | 72% | 85% | 94% | 97% |
| 보통 | 16 | 36% | 55% | 72% | 79% |
| 어려움 | 20 | 10% | 21% | 36% | 45% |

### 3.3 보정치
1. 보정치 = 스탯 보정 + 스킬 보정 + 호감도 보정 + 정보 보정 + 영주 보정 + 기적 보정 + 기타의 합 [확정]
2. **스탯 보정 = 스탯 수치 그대로** (`stats.md` 변환표, 변환 계수 없음) [확정] (D-035)
   - 국면에 스탯이 2개면 두 수치를 합산한다 (D-018). 예: 헤라클레스 정면 격돌 = 근력 7.5 + 내구 7 = 14.5
3. 보정 상한 [확정] (D-073):
   - **대항 판정에서 양측 보정 차이를 최대 15로 절삭** → `dice.modifier_gap_cap` = 15
   - 근거: 2d10 두 개의 자연값 차이는 최대 18이다. 보정 차이가 18 이상이면 약자 승률이 0%가 되어 §4 불변 조건이 깨진다. 차이 15에서 약자 승률은 0.15%, 16은 0.05%.
   - 대안: 각자 보정 합에 상한을 두는 방식. 스탯 합산(최대 16)과 섞이면 계산이 복잡해져서 차이 상한을 제안한다.

### 3.4 잭팟(기적) [확정]
1. 자연값이 서번트의 행운 구간에 들어오면 기적이 발동한다.
2. 행운 랭크별 구간 (2d10 자연값) → `dice.miracle_range`
   | 행운 랭크 | 기적 구간 | 발동 확률 |
   |---|---|---|
   | EX | 18, 19, 20 | 6% |
   | A ~ B | 19, 20 | 3% |
   | C 이하 | 20 | 1% |
   - ± 랭크는 문자 기준으로 분류한다 [확정] (D-073). 예: A+ → A ~ B 구간, B- → A ~ B 구간, C+ → C 이하 구간
3. 기적의 효과: **보정 +5** [확정] (D-036) → `dice.miracle_bonus` = 5
   - 기적 보정은 §3.3 차이 상한 **밖**에서 더한다 [확정] (D-073)

### 3.5 운명점 재굴림 [확정] (D-010, D-038)
1. 굴림 후 운명점 1을 소모해 다시 굴린다. 재굴림 결과를 쓴다.
2. 초기값 **3** → `dice.fate_point_init` = 3
3. **게임 시작 전에 개수를 고른다** [확정] (D-081, D-095). 범위 **0 ~ 99** (D-127), 기본값 3, `+`/`-` 버튼으로 조정 → `dice.fate_point_min` = 0, `dice.fate_point_max` = 99. 많이 고른 대가: 없음 (Q-151 답에 언급 없음)
4. 게임 중에는 회복하지 않는다.
5. 한 판정에서 여러 번 재굴림할 수 있다 [확정] (D-081)
6. 재굴림은 **판정이 실패했을 때만** 묻는다 [확정] (D-119). 대항은 상대보다 낮을 때, 단독은 목표 미달일 때, 마력 공급은 실패·대실패일 때
7. 재굴림은 플레이어 서번트의 굴림에만 쓴다. 적 AI는 재굴림하지 않는다 (§3.6: 상대 굴림은 자동)

### 3.6 굴리는 주체 [확정] (D-073)
대부분의 판정은 유저가 직접 굴린다. 자동 처리 목록:
| 판정 | 처리 | 이유 |
|---|---|---|
| 내 서번트의 국면 판정 | **유저** | 핵심 연출 |
| 낮 행동 판정 (정보 수집, 마력 공급 등) | **유저** | |
| 도주 판정 | **유저** | |
| 상대 측의 모든 굴림 | 자동 | 상대 주사위는 연출만 |
| 적끼리 전투 전체 | 자동 | `combat.md` §8 |
| 국면 유형 추첨, 공격/방어 추첨 | 자동 | 판정이 아니라 추첨 |
| 명령 거부·배신 확률 판정 | 자동 | `affinity.md` §3.4 |
| 적 AI 이동, 3진영 이상 대진 추첨 | 자동 | |
| 강제 전투 대진 추첨 | 자동 | |

### 3.7 무작위 [확정]
모든 무작위는 시드 RNG 모듈을 통한다. 같은 시드 + 같은 입력 = 같은 결과.

### 3.8 방심: 폐기 (D-037)

## 4. 불변 조건 [확정]
- 어떤 스탯/보정 격차에서도 약자 승률 > 0% (§3.3 차이 상한으로 보장)
- 헤드리스 시뮬레이션 테스트로 검증한다

## 5. 참고: 2d10 대항 판정 확률 (보정 차이별, 계산값)
| 보정 차이 | 약자 승 | 동점 |
|---|---|---|
| 0 | 46.7% | 6.7% |
| 3 | 27.8% | 5.9% |
| 6 | 13.5% | 4.2% |
| 10 | 3.3% | 1.7% |
| 15 | 0.15% | 0.1% |

## 6. 엣지 케이스
| 상황 | 기대 동작 |
|---|---|
| 양쪽 모두 기적 발동 | 양쪽 모두 +5. 결과는 판정값 비교 |
| 보정 차이가 상한 초과 | 강한 쪽 보정을 깎아 차이를 15로 맞춤 [제안] |
| 운명점 0에서 재굴림 시도 | 불가, 이유 텍스트 출력 |

## 7. 예시 (테스트 케이스)
1. **기본 대항:** 헤라클레스 정면 격돌 14.5 vs 메데이아 7. 자연값 9 vs 15 → 23.5 vs 22 → 헤라클레스 승, 차이 1.5
2. **기적:** 코지로(행운 A → 구간 19~20) 선제/회피 7.5 vs 헤라클레스 민첩 7. 코지로 자연값 19 → 기적 +5 → 7.5 + 19 + 5 = 31.5. 헤라클레스(행운 B → 구간 19~20) 자연값 18 → 기적 없음 → 25 → 코지로 승, 차이 6.5
3. **차이 상한:** 보정 25 vs 5 (차이 20) → 강한 쪽을 20으로 절삭 (차이 15). 이후 기적 +5는 상한 밖이라 그대로 더함
4. **운명점:** 운명점 3에서 재굴림 → 2. 운명점 0에서 재굴림 → 거부

## 8. 의존성
- 읽는 값: 스탯(`stats.md`), 스킬(`skills.md`), 호감도(`affinity.md`), 정보(`day-loop.md`), 영주(`combat.md`)
- 쓰는 값: 운명점, 이벤트 로그

## 9. 미정 사항
- 보정 차이 상한 초과 시 강한 쪽을 깎는 방식 (§6 제안. §7 예시 3과 같은 방식으로 구현됨)
