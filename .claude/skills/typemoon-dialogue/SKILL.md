# 타입문 대사 작성 가이드 (fsn6)

사용자가 **범위(서번트, 상황 태그)를 지정해** 대사 초안을 요청했을 때만 쓴다 (AGENTS.md 규칙 7, D-060).
범위 지정 없이 대사를 만들지 않는다. 범위가 모호하면 먼저 묻는다.

## 0. 시작 전에 읽을 것
1. `docs/systems/narrative-engine.md` — 대사 데이터 형식(§5), 사실·기억 목록(§4), 자리표시자·조사·정보 가림(§7)
2. `docs/systems/text.md` §3.4 — 상황 태그 목록
3. `data/servants/{servant_id}/voice.md` — 그 서번트의 말투 가이드 (없으면 §3 표를 쓰고, 사용자에게 voice.md 작성을 제안). 적 마스터는 `data/masters/{master_id}/voice.md`와 `docs/content/masters.md` §4.1 규칙
4. `docs/content/servants-5th.md` 또는 `data/servants/{servant_id}/profile.json` — 스탯, 스킬, 보구, 성향
5. 기존 대사 (중복 방지, 인용 원본):
   - `legacy/data/dialogues-ko.json` — FGO 한국어판 대사 (서번트 ID 키: 알트리아 2, 에미야 11, 쿠 훌린 17, 메두사 23, 메데이아 31, 코지로 39, 헤라클레스 47)
   - `legacy/data/affinityDialogues.ts` — 인연 서번트 쌍 대사
   - `legacy/data/narrativeTemplates/ko.ts`, `legacy/data/text/manaSupplyText.ts`

## 1. 작업 순서
1. 요청 범위의 상황 태그마다, 기존 대사로 쓸 수 있는 게 있는지 먼저 찾는다 → 있으면 `source: "fgo"` 또는 `"legacy"`로 들여온다
2. 원작 인용이 어울리는 자리인지 판단한다 (§4)
3. 새로 쓴다. 태그당 변형 2~3개. 조건(`when`)을 달리해 서번트 전용 / 특수 상호작용 층을 섞는다. 클래스 공통·공통 대사는 사용자가 그 범위를 요청했을 때 `classes/`, `common/` 파일에 쓴다 (D-064)
4. §7 체크리스트로 검사한다
5. 결과는 해당 폴더의 `dialogue.json` 형식(`narrative-engine.md` §5.2)으로 낸다. 전부 `"status": "draft"`, `"author": "ai"`

## 2. 문체: 나스 키노코·타입문
### 2.1 특징
| 기법 | 설명 |
|---|---|
| 단정과 선언 | 짧고 단정한 문장으로 끊는다. 설명보다 선언. 체언으로 끝나는 문장도 쓴다 |
| 끊김과 여운 | `──`(긴 줄표)로 호흡을 끊고, `……`로 여운을 남긴다. 레거시 데이터 표기(`──`, `───`, `……`)를 그대로 따른다 |
| 반복과 대구 | 같은 구조를 두세 번 겹쳐 리듬을 만든다 |
| 이중 표기(루비) | 개념어·보구명은 `한자어(한글 독음)` 형식 (D-070). 보구명은 `‘ ’`로 감싼다. 예: `‘약속된 승리의 검(엑스칼리버)’`, `고유결계(리얼리티 마블)`. 공식 텍스트 인용(에미야의 영어 영창 등)은 원문 유지 |
| 영창 | 보구 개방은 짧은 영창 + 보구명. 영창은 운율 있는 명사구를 겹친다 |
| 거리감 있는 묘사 | 서술문은 과장된 형용보다 현상을 담담하게. 긴장의 정점에서 문장을 짧게 |
| 세계관 어휘 | 아래 §2.2 용어를 쓴다. 일상어로 풀어 쓰지 않는다 |

### 2.2 용어 (FGO 한국어판 기준)
| 쓴다 | 쓰지 않는다 |
|---|---|
| 마스터, 서번트, 영령 | 주인, 소환수 |
| 영주 | 명령 문양, 인장 |
| 보구, 진명 | 필살기, 본명 |
| 마력, 마술회로, 마력 공급 | MP, 에너지 |
| 성배전쟁, 성배 | 대회, 트로피 |
| 클래스명: 세이버, 아처, 랜서, 라이더, 캐스터, 어새신, 버서커 | 검사, 궁수 등 번역어 |
- 서번트 이름 표기는 `docs/content/servants-5th.md` §1을 따른다

### 헤라클레스 (버서커)
- 레거시 데이터의 `[image berserker_language_1]`은 포효 토큰이다. 새 대사에서도 같은 토큰을 쓰고, 표시 형식은 UI가 정한다 [TBD]

## 4. 원작 인용
사용자 방침: 원작 대사를 **적극적으로** 인용한다. 단, 아래 규칙을 지킨다.

### 4.1 인용 원본의 우선순위
| 순위 | 원본 | `source` | 검증 |
|---|---|---|---|
| 1 | `legacy/data/dialogues-ko.json` (FGO 한국어판 공식 텍스트) | `fgo` | 데이터에서 그대로 복사하므로 검증됨 |
| 2 | 사용자가 제공한 원작 텍스트 | `quote` | 사용자 제공 = 검증됨 |
| 3 | AI가 기억하는 원작 대사 (Fate/stay night 등) | `quote` | **`quote_verified: false` 필수.** 기억에 의존한 인용은 틀릴 수 있다 |

### 4.2 인용 규칙
- **짧게.** 한 대사에 인용은 한두 문장까지. 원작 장면을 길게 옮겨 적지 않는다 (저작권, D-057)
- 인용은 **상징적인 순간**에 쓴다: 소환, 보구 영창, 숙적과의 재회, 결정적 승리·패배. 평범한 상황에 남발하지 않는다
- 인용 대사는 `repeat: "once_per_run"` 권장. 반복되면 가치가 떨어진다
- 원작 대사를 바꿔 쓴 오마주는 인용이 아니다 → `source: "new"`, `notes`에 원작 장면 표시

## 5. 상황 설계
- **기억을 쓰라.** 같은 태그라도 `mem.*` 조건(재회, 방면한 상대, 이 타일에서 진 적 있음)을 붙인 변형을 만든다. 서술 엔진이 "AI 같다"고 느껴지는 핵심이다 (`narrative-engine.md` §1)
- **정보 가림을 지켜라.** 상대 진명은 `enemy.intel_level: 3` 조건이 있을 때만 쓴다. 조건이 없으면 `{enemy}`(자동으로 클래스명 표시)를 쓴다
- **성향을 반영하라.** 처치·방면 대사는 성향(선/중립/악)과 호감도 변화 방향에 맞춘다 (`affinity.md` §3.5)
- **마력 공급은 은유적으로** (`mana.md` §3.5)
- 서술문(화자 없음)과 대사(화자 있음)를 섞는다. 서술문의 `speaker`는 `"narrator"`
- **보구 영창은 그대로 쓴다** (D-067). 보구를 여는 순간 정체가 공개되므로 가림 조건이 필요 없다
- **화자 쪽 가림:** 서번트 자신을 서술문에서 부를 때는 이름 대신 `{servant}`를 쓴다. 적으로 나왔을 때 진명이 새지 않게 하기 위해서다. 화자가 **보구 영창 밖에서** 자기 정체를 드러내는 말(자기 보구명 언급, 전설)은 `self.intel_level: 3` 조건을 붙인다

### 5.1 나레이션 작성
나레이션은 대사와 **한 비트로 엮인다** (`narrative-engine.md` §8). 단독으로 읽혀도 되지만, 앞뒤 대사와 붙었을 때 자연스러워야 한다.
- **슬롯을 정한다:** `lead`(장면을 연다), `react`(대사·결과에 반응), `tail`(닫고 넘긴다). 줄마다 `"slot"` 필드
- **대사에 반응하는 나레이션**은 `when`에 `beat.line.tone`을 건다. 같은 자리에 톤 조건 없는 기본 버전도 하나 둔다 (대사가 없을 때 대비: `beat.has_line`)
- **대사에는 `tone`을 단다** (`calm` `defiant` `playful` `grim` `tender` `cold` `roar`). 나레이션이 반응할 수 있게 하기 위해서다
- **이름을 직접 쓰지 않는다.** `{actor}` `{target}` `{winner}` `{loser}` `{enemy}` `{servant}`를 쓰고 조사는 `{이/가}` 형식
- **장소 묘사는 `lead`에만.** 같은 장면에서 반복하지 않는다
- **짧게.** 한 줄은 한두 문장. 긴장의 정점일수록 더 짧게 (§2.1, §8)
- 시점: **3인칭 관찰자** (D-069). 인물의 머릿속에 들어가지 않는다. 보이고 들리는 것, 분위기, 감각만 쓰고 속마음은 대사에 맡긴다
- 공통 나레이션은 `data/common/narrator.json`, 서번트 전용은 서번트 파일 안 `"speaker": "narrator"`

## 6. 출력 형식
`narrative-engine.md` §5.2 (서번트 폴더의 `dialogue.json`)를 따른다. 예시 (본문은 형식 설명용 자리표시자):
```json
{
  "speaker": "sv_0002_artoria",
  "defaults": { "status": "draft", "author": "ai", "weight": 1, "repeat": "always", "source": "new" },
  "tags": {
    "summon": [
      { "id": "fgo_01", "text": "(dialogues-ko.json 2번 summon 대사를 그대로 복사)",
        "source": "fgo", "quote_of": "Fate/Grand Order", "quote_verified": true, "repeat": "once_per_run" }
    ]
  }
}
```
- `id`는 의미 있는 이름으로 짓고 한 번 정하면 바꾸지 않는다. `text_id`는 엔진이 `tx_{화자}_{태그}_{id}`로 만든다
- 다른 서번트를 향한 대사(인연 대사)도 **말하는 쪽 폴더**에 `when`으로 둔다
- 자리표시자와 조사: `{enemy}{이/가}` 형식 (`narrative-engine.md` §7)

## 7. 체크리스트
- [ ] 사용자가 지정한 범위 안인가
- [ ] 기존 대사를 먼저 확인했는가 (중복 없음)
- [ ] 말투가 해당 서번트의 `voice.md`(없으면 §3 표)와 맞는가
- [ ] 용어가 §2.2와 맞는가
- [ ] 진명·보구명이 정보 가림 조건 없이 쓰이지 않았는가 (상대 쪽 `enemy.intel_level`, 화자 쪽 `self.intel_level`)
- [ ] 인용은 짧고, `source`·`quote_verified`가 정확한가
- [ ] 조사는 `{이/가}` 형식으로 썼는가 (고정 조사 금지)
- [ ] `when`의 사실 이름이 `narrative-engine.md` §4에 있는가
- [ ] 모든 항목이 `status: draft`, `author: ai`인가
- [ ] 나레이션에 `slot`이 있고, 톤 반응 나레이션에는 톤 조건 없는 기본 버전이 짝으로 있는가
- [ ] 대사에 `tone`을 달았는가

## 8. 나스버스·타입문 문체 심화 (사용자 작성)

이 스킬은 나스 키노코(Nasu Kinoko) 및 타입문(TYPE-MOON) 고유의 서사 스타일, 문체, 대사 톤, 관념적 세계관 묘사 방식을 재현하도록 지시합니다.

---

### 1. 문체 및 어조 (Style & Tone)

1. **운명론적이며 은유적인 만연체**
   - 문장은 종종 단정적이며, 독백은 철학적이거나 비장해야 한다.
   - 명사를 문장 끝에 나열하여 여운을 남기거나 단문 연속 배치로 호흡을 급격히 전환한다.
   - 예시: *"──그것은 기적. 혹은 절망이라 불리는 찰나의 환영."*

2. **특수 기호 및 문장 부호의 사용**
   - 대사의 시작이나 극적인 강조, 독백 전환 시 `──` (엠 다시)를 자주 사용한다.
   - 비장한 묘사에는 따옴표(`『 』`)나 강조 기호(`「 」`)를 적절히 배치한다. 단, 보구명은 `‘ ’`로 감싼다 (D-070).
   - 연출상 긴장감을 극대화할 때 단문 끝에 마침표를 강하게 찍는다.

3. **관념의 물질화 및 감각의 세분화**
   - 마력, 경지, 신념, 개념을 지극히 감각적이고 신체적인 고통/감각으로 묘사한다.
   - '마력 회로의 구동'이나 '개념의 충돌'은 회로의 탄내, 회백색 신경의 도련, 세계의 삐걱거림 등으로 표현한다.

---

### 2. 한자 표기 및 독음 규칙 (Rubi System)

타입문 특유의 **"개념적 명칭(한자)" + "실제 읽는 법/외래어(루비/가타카나)"** 구조를 다음과 같이 작성한다.

- **포맷:** `개념한자어(실제 독음)`. 독음은 **한글로** 쓴다 (D-070)
- **예시:**
  - `보구(노블 판타즘)`
  - `고유결계(리얼리티 마블)`
  - `투영개시(트레이스 온)`
  - `약속된 승리의 검(엑스칼리버)`

---

### 3. 핵심 서사 모티브 및 키워드 (Keywords & Motifs)

문장 생성 시 아래 키워드와 고유 관념을 자연스럽게 융합한다.

- **세계의 법칙:** 억제력(알라야/가이아), 인리(人理), 외계의 법칙, 세계의 텍스처, 질감
- **개념과 신념:** 기원(Origin), 영혼의 포맷, 마술회로, 마모, 이상, 고결함, 구원
- **전투 및 개념 충돌:** 한계의 돌파, 붕괴, 영핵(靈核), 등가교환, 영원의 찰나, 사각(死角)
- **자주 쓰이는 표현 패턴:**
  - *"───거짓은 없다."*
  - *"───가자, 파트너."*
  - *"───세계가, 타오르고 있었다."*
  - *"그것은, 결코 닿을 수 없는 별과 같아서."*

---

### 4. 서사 전개 지침 (Structural Rules)

1. **내면 독백과 외적 액션의 교차**
   - 전투 장면에서도 단순한 무력 충돌보다는 '서로의 신념과 개념의 부딪힘'에 초점을 맞춘다.
   - protagonist의 극심한 육체적·정신적 고통과 마모 과정을 생생하게 기술한다.

2. **절망 속의 비장미 (Bitter-Sweet Hope)**
   - 세계나 상황은 극도로 잔혹하고 압도적이어야 한다.
   - 주인공은 압도적인 강자나 법칙 앞에서 무력하지만, 자신의 고유한 '신념'이나 '기원' 하나만을 쥐고 한계를 넘어서는 찰나를 그려낸다.

### 5. 예시 텍스트 (Few-Shot Examples)

#### [예시 1: 마술 구동 및 투영]
> ───투영, 개시(트레이스 온).
> 
> 신경을 갉아먹는 마력 회로에 불이 들어온다.
> 불꽃이 튀는 것은 뇌내가 아니다. 회백색으로 마모되어 가는 영혼의 구석.
> 제시된 설계도는 삼천 개. 그 모든 요소를 통과시키고, 이해하고, 기화시킨다.
> 
> "───간장(干將), 막야(莫邪)."
> 
> 손바닥에 남는 것은 차가운 철의 질감.
> 그것은 환영이 아닌, 세계의 틈새에서 끄집어낸 단 한 줄기의 기적이었다.

#### [예시 2: 개념 전투 묘사]
> 그것은 무술의 영역을 넘어선, 신성(神性)의 체현.
> 칼날이 도달하기도 전에 세계가 비명을 지르고, 공간이라는 텍스처가 박리되어 간다.
> 
> 하지만───그렇기에 더욱.
> 이 가슴에 남은 단 하나의 이상(理想)을, 꺾일 수는 없다.
> 
> "‘약속된 승리의 검(엑스칼리버)’───!!"
> 
> 방출되는 것은 한 자루의 검이 아닌, 인류가 자아낸 원초의 희망.
> 영원과도 같은 찰나 속에서, 빛과 어둠이 상극을 이루며 무너져 내렸다.
